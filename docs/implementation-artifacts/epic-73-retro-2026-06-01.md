## What went well

- **Approved on first submission.** No rejection cycle. For a first-time submission from a new developer account, this is not the default outcome.
- **Upstream investment paid off.** The epics that mattered for approval (69, 70, 71, 72) had already done the work. Epic 73 was largely assembly + click submit.
- **Privacy-by-design simplified the questionnaire.** No analytics SDKs, no network calls, no tracking → "No Data Collected" → one-question privacy section.
- **Field-discovery friction documented inline.** Stories 73.1–73.3 each contain "Common First-Time Pitfalls" and "Field-discovery friction" subsections capturing real ASC UI quirks (drop zone gating, draft/publish split, copyright field location, misleading hint copy on the App Review Notes field). This is reusable institutional knowledge.

## What was harder than the story files suggested

**The story-level effort framing systematically undersold the work.** Stories 73.1–73.3 were described as "manual", "single button click", "2 minutes". Michael reported the actual work took several hours.

Where the hours went:

1. **App Store Connect German localization is sometimes bad and occasionally misleading.** ASC honors the browser/account language. When the UI is in German and Apple's developer docs are in English, the field names and section titles don't line up. Bad translations forced extra interpretation and lookup. **Fix for next time: switch the ASC interface to English before doing submission work.**
2. **Decision-heavy, not click-heavy.** Inside the "manual" framing of 73.1 alone, at least eight non-trivial judgment calls had to be made (category choice, German subtitle wording at 30-char limit, Content Rights answer with SoundFont license rationale, iPad-on-Mac toggle, Universal Purchase deferral reasoning, License Agreement, last-compatible-version setting, copyright field location).
3. **Blocking UI quirks until discovered.** Three friction points were blockers without the workaround: screenshot drop zone gates on display-size picker state (73.2); privacy questionnaire has a draft/published distinction not in Apple's docs — "Save" creates a draft, "Publish" is the separate required action (73.3); copyright field lives on the version page, not App Information (73.1).
4. **Sprint-status drift surfaced at the last moment.** Story 69.3 was obsolete (icon migrated to `.icon` package; PNG no longer exists) and 69.4 was done-but-not-marked. Neither blocked submission, but both became visible only when the dev-story workflow checked prerequisites.

## Key insights

- Operational stories framed as "manual" / "just a button" can still consume hours due to UI friction, localization decisions, and judgment calls. Treat that framing as a *floor* on effort, not a description of it.
- ASC's German localization is a friction multiplier on top of an already form-heavy tool. English UI removes that.
- Documenting field-discovery friction inline is high-leverage: the knowledge would otherwise evaporate before the next submission.
- Submission stories depend heavily on upstream work being correct. The fact that 73 went smoothly is a verdict on 69–72, not on 73 itself.
